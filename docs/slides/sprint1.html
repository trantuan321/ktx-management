03 · Kiến trúc

Kiến trúc 3 lớp & công nghệ

🖥️ Client – React 18 + Vite 6React Router 6 · 9 trang · layout dùng chung · menu theo vai trò · gọi REST API qua fetch
⚙️ API – Node.js 24 + Express 48 nhóm route · middleware xác thực/phân quyền · scrypt + token HS256 · transaction chống xếp trùng
🗄️ Dữ liệu – SQLite (node:sqlite)schema.sql · 10 bảng · unique index · seed dữ liệu mẫu · không cần cài máy chủ CSDL

Vì sao SQLite?

Cả nhóm clone là chạy, không cài MySQL; file đơn dễ backup; SQL thuần dễ chuyển đổi sau này.

Vì sao tách FE/BE?

REST API rõ ràng, dễ test độc lập; frontend build tĩnh, backend có thể triển khai riêng.

An toàn dữ liệu

Mật khẩu băm scrypt; token có hạn 12 giờ; quyền kiểm tra ở cả API và giao diện.

04 · Dữ liệu

ERD rút gọn – 6 bảng cốt lõi Sprint 1

buildings (id, code, name, gender, floors) └─< rooms (id, building_id, code, floor, capacity, price, status) └─< beds (id, room_id, code, status) ← mỗi giường 1 sinh viên └─| students (id, mssv, full_name, class, bed_id) ├─< applications (id, student_id, status, assigned_bed_id) └─| users (id, username, password_hash, role, student_id)

Ràng buộc then chốt

UNIQUE MSSV · UNIQUE (building_id, code) · UNIQUE (room_id, code)

Chống xếp trùng

Unique index trên students(bed_id) + transaction BEGIN IMMEDIATE khi duyệt đơn.

Một đơn chờ / SV

Partial unique index (student_id) WHERE status='pending'.

Các bảng contracts, invoices, notifications, maintenance_requests đã thiết kế sẵn cho Sprint 2.

06 · Chức năng

Đăng nhập & phân quyền

Luồng xác thực

  • Đăng nhập → kiểm tra scrypt → ký token HS256 (12 giờ)
  • Client lưu token, gửi kèm Authorization: Bearer
  • Server nạp lại user mỗi request → khóa tài khoản có hiệu lực ngay
  • Sai mật khẩu trả 401, không lộ tài khoản có tồn tại
  • Client nhận 401 → xóa token, về trang đăng nhập

Kiểm soát quyền 2 lớp

  • Giao diện: menu lọc theo vai trò, RequireRole chặn route
  • API: authenticate + authorize(roles)
  • SV gọi API quản lý → 403
  • Manager gọi API admin → 403
  • Không token → 401

07 · Chức năng

Tòa nhà – Phòng – Giường

Quản lý

  • CRUD tòa nhà: mã, tên, giới tính, số tầng, địa chỉ
  • CRUD phòng: tòa, mã, tầng, sức chứa, loại, giá, trạng thái
  • Tạo phòng tự sinh giường G1…Gn theo sức chứa
  • Thêm/xóa giường, chuyển trạng thái trống ↔ bảo trì
  • Chặn xóa tòa nhà/phòng/giường đang có sinh viên ở

Tìm phòng trống

  • Bộ lọc theo tòa, trạng thái, từ khóa
  • Checkbox “Chỉ phòng còn trống”
  • Bảng hiển thị sức chứa, đã ở, số giường trống
  • SV xem dạng thẻ phòng trực quan, có giá/tháng
  • Chặn thêm giường vượt sức chứa 409

08 · Chức năng

Hồ sơ sinh viên nội trú

Thông tin quản lý

  • MSSV, họ tên, giới tính, ngày sinh
  • Lớp, khoa, điện thoại, email, địa chỉ
  • Trạng thái: đang hoạt động / ngừng
  • Giường hiện tại (nếu đang nội trú)

Tra cứu & ràng buộc

  • Tìm theo MSSV, họ tên hoặc lớp (LIKE)
  • Lọc theo trạng thái và tình trạng nội trú
  • MSSV duy nhất — trùng báo 409
  • Không xóa sinh viên đang nội trú
  • SV chỉ xem hồ sơ của chính mình

Dữ liệu mẫu: 6 sinh viên, 6 tài khoản SV, 4 sinh viên đã được xếp chỗ.

09 · Chức năng cốt lõi

Đăng ký ở & xếp chỗ

SV xem phòng trống
→
Gửi đơn + nguyện vọng
→
Quản lý chọn phòng & giường
→
Duyệt trong transaction
→
SV thấy phòng/giường

Kiểm tra khi duyệt

  • Đơn phải đang pending
  • Sinh viên chưa có giường
  • Giường đang available
  • Phòng đang hoạt động và chưa đầy

Chống xếp trùng

  • BEGIN IMMEDIATE bao toàn bộ thao tác
  • Cập nhật giường → sinh viên → đơn trong cùng transaction
  • Unique index students(bed_id) là lớp bảo vệ cuối
  • Vi phạm → 409, dữ liệu rollback
